# 迁移与恢复

## 正常搬盘

1. 停止提交任务。等待现有任务完成，或在界面明确取消。
2. 执行 `PREPARE_MIGRATION.ps1`。必要时显式传 `-CancelActive` 取消本项目任务。脚本核验服务 PID/命令/UUID，停止本项目进程，sync 后只 terminate 本项目发行版。
3. 脚本只能确认本项目停止；请自行确认盘上的其它软件、文件或 MD 任务已释放，再安全拔盘。不得运行中复制 VHDX。
4. 在新的 Windows x86-64、已有可用 WSL2 的电脑，把整个目录放在任意盘符，执行 `REGISTER_ON_THIS_PC.ps1`。脚本按当前 VHDX 绝对路径与 UUID 识别注册，优先 import-in-place；名字冲突使用新名字，保留现有环境。
5. 重新运行 doctor、CCO 验收；GNINA 在新硬件上重新执行 GPU/CPU smoke。硬件变化会清除旧设备验证状态。随后双击 START_WINDOWS.cmd。

源码通过当前目录和 wslpath 得到 SBVS_PROJECT_ROOT。内部 Python 前缀 `/opt/sbvs/` 保存在 ext4 中，换盘符不重装依赖。宿主 WSL、其登记信息以及 Windows GPU 驱动由新电脑提供，不在便携包内。

WSL 不支持 import-in-place 时明确更新宿主 WSL；脚本不会自动更新 Windows，不会设默认发行版。不要自动或手动把 `wsl --unregister` 当安全解绑操作，它可能删除虚拟磁盘。

## 离线恢复快照

执行 `EXPORT_RUNTIME.ps1` 会先安全停止本项目，再 `wsl --export` 导出 tar 到 runtime/downloads，生成 SHA256 清单。仅导出本项目，不复制用户原有 Ubuntu。这个大文件备份不是每次启动的步骤。

恢复 tar 时在新的独立目录手动用 `wsl --import <唯一名称> <新runtime目录> <快照tar> --version 2`，核验 `/opt/sbvs/project_uuid` 后使用项目启动器。保留原始镜像直到恢复测试通过。

## 中断与续跑

服务异常结束后，启动时将原 running/preparing 标为 interrupted，并仅清理身份匹配的遗留本项目引擎子进程。CLI `resume --run` 或任务恢复接口复用已完成且校验正确的条目，继续未完成/失败条目。取消不会被写成 completed。

本机已测试：同机中文空格目录下的新 run、Windows 路径转发、现有 VHDX 注册识别、安全停止/重启、断网运行。另一台实际电脑、完整 VHDX 复制后重新注册、Windows ARM、WSL1 未视为已通过。详细状态以验收报告为准。
