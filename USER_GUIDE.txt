Yuanhe Bio: use the administrator-provided UI link

After deploying the GitHub project and configuring dependencies, models, GPUs and data directories, the administrator shares the workbench URL. Open it to operate the page manually or authorize Codex to operate the same page. Users need no local computation environment, terminal or separate launch entry point.

1. Create a research run
Select the structure, chains and residue ranges, and confirm the actual inputs. Historical GNINA, AM1-BCC or short-MD runs retain their original identities and protocols. Create a new run after migration.

2. Prepare the receptor and search box
Complete complex preparation. In Tool 1, inspect the receptor, protonation assumptions, missing atoms, membrane-protein construct and search box. Both center coordinates and side lengths are in angstroms. Preview, then save the review.

3. Generate and dock
Generate molecules and review retained molecular cores in Tool 2. Docking stage settings use official AutoDock Vina 1.2.7; standard defaults are exhaustiveness=32, num_modes=9 and energy_range=3 kcal/mol. Research profiles have their own frozen stage settings. Concurrent CPU tasks multiplied by threads per task must not exceed the total thread budget. A docking seed array does not increase MD replica count.
Lower vina_affinity_kcal_mol is better; CNN fields are not applicable. Inspect actual logs, failure reasons and selected poses. Do not directly mix historical GNINA scores into the ranking.

4. Screen and hand off poses
Choose screening depth in Tool 3 and distinguish preliminary, formally qualified and exploratory candidates. Confirm that compound_id, state_id and pose_id match the final selected pose. Docking scores and screening qualification do not establish biological activity.

5. Build one MD trajectory
Select the final candidate in Tool 4 and review membrane orientation, lipids, salt concentration and temperature. Defaults are GAFF2 with HF/6-31G* ESP and two-stage RESP, and one 500 ns production trajectory. Minimization, heating and equilibration are additional. The QM-optimized conformation is for parameterization and does not replace the bound pose; failure never falls back to AM1-BCC.
Configure the initial velocity seed, GPU index, output interval, checkpoint interval, QM threads and stable backbone/transmembrane core alignment selection. Default output and checkpoint intervals are 10 ps and 2 minutes.
MurJ uses an explicit membrane. The built-in single-lipid membrane is not a complete mixed bacterial membrane. Enter and review membrane PB thickness, dielectric, pore model and supporting evidence before building.

6. Run and resume
Preview the built system in Tool 5 and confirm identity, parameters, orientation and protocol. Select Start / Resume from checkpoint, or execute through the sixth stage. The default is one trajectory for that system; extra trajectories in Tool 7 are not required.
After stopping, wait for checkpoint writing, reopen the same run and system, and use the same button to resume. Do not create a replacement system or change frozen inputs. Missing matching checkpoints or changed inputs block resumption.

7. Analyze and inspect
Use Analyze completed production trajectory and inspect trajectories, curves and raw records in Tool 6. Core metrics are the mean and sample standard deviation of ligand heavy-atom RMSD over 400–500 ns after alignment to the specified protein backbone/transmembrane core. Between-replica statistics are not applicable to one trajectory.
MM/PBSA uses the same trajectory, by default 400–500 ns and every tenth saved frame. Adjust the PB window, sampling interval and dielectric settings before building. Membrane systems require a reviewed membrane PB model. Reports distinguish framewise standard deviation from the uncertainty of the mean accounting for time correlation; entropy is excluded.
Trajectories shorter than 500 ns do not produce formal final-window conclusions. Reaching 500 ns or obtaining low standard deviation does not establish stability, convergence, strong binding or activity; extension may be needed.

8. Export
Use Export reproduction records for inputs, frozen configuration, logs and analysis. Select the full archive when raw trajectories are needed. Administrators retain installed environments and model weights separately.
