The installer now applies hash-verified patches to the pinned REINVENT4 dependency manifest and lock, selecting official torch 2.12.0+cu130 and torchvision 0.27.0+cu130. Only their CUDA dependency family changes; other package versions and sources are preserved. Existing sampling patches, priors, scientific thresholds and production protocols are unchanged. Dependency metadata is checked as source data; only Python module patches are checked through the installed import path.

Use the updated site template, a clean source directory and a new runtime prefix. Preserve a failed installation and its logs. Do not replace Torch manually in a partially installed environment, disable the CUDA check, or silently switch REINVENT to CPU.

The hf-resp/5 revision uses the native [Psi4 1.11 geomeTRIC adapter](https://raw.githubusercontent.com/psi4/psi4/v1.11/psi4/driver/driver.py), with geomeTRIC 1.1.1 pinned in the original Conda lock and required by readiness. HF/6-31G*, PK SCF, tight electronic convergence, force limits, two-stage RESP, explicit chemical state and the bound pose remain unchanged.

The pinned optimizer computes aligned Cartesian per-atom displacement norms in angstrom ([implementation](https://raw.githubusercontent.com/leeping/geomeTRIC/1.1.1/geometric/step.py)), although its option prose and Psi4 log heading call them atomic units. Explicit RMS and maximum limits, 2.1167088e-5 and 3.1750632e-5 angstrom, round down the prior 4e-5 and 6e-5 bohr values. Its per-atom gradient norms and an additional 1e-6 hartree energy condition must also pass; hitting the iteration limit is never success. This changes the numerical optimizer and metrics, not the charge model. The new schema rejects old charge caches; versioned source hashes retain earlier revisions. A fresh original-flow installation and real UI build, short MD and analysis are still required.
